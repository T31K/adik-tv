# ADIK Stream — encrypted R2 streaming, readable only on paired TVs

_Status: design, awaiting approval · 2026-11-27_

## 1. Intent

A second version of ADIK TV that **streams movies from a private Cloudflare R2 bucket** instead of
torrenting them onto a USB drive. The files in R2 are **encrypted chunks that only a paired TV can
decrypt**: each TV holds its own private key inside Android Keystore, and that key never leaves the TV.

Why (from the conversation and the project state): the USB drive on Mom's TV failed and torrent
downloads stall, and the owner wants R2 to hold only unreadable bytes. The first title is the owner's
own disc rip of *Demon Slayer: Infinity Castle* (2.3 GB, HEVC Main10 1080p, AAC 5.1 jpn, SRT eng + PGS jpn,
~2.1 Mbps).

## 2. Goals / non-goals / anti-goals

**Goals**
- R2 stores only ciphertext under opaque names; Cloudflare and anyone with a link see random bytes.
- Only a TV the owner approved can decrypt a movie; revoking a TV takes one server change and no re-upload.
- Seeking works (jump to any chunk without reading the rest).
- Plays in the existing libVLC player with audio + subtitle tracks intact.
- One-way flow: the Mac encrypts + uploads; TVs only fetch + decrypt; nothing flows back except pairing.

**Non-goals (v1)**
- Replacing the torrent version. It stays as is on Mom's TV and the fleet (see §5, Variant).
- Offline playback / caching whole movies on the TV.
- Series/episodes (movies only first; the format works per file, so episodes come later for free).
- Per-TV movie lists. v1 is a test on **one TV (living-room TCL)**: every approved device sees every stream
  movie. Per-device lists (like `adik_device_items`) come later if this goes to the fleet.
- Protection against a skilled attacker with root on a paired TV. Nothing can fully stop that, because
  the decrypted frames have to reach the screen.

**Anti-goals (a failure even if it works)**
- Any Cloudflare/R2 spend without the owner's OK. R2's free tier is 10 GB of storage **across the whole
  account**. One movie is fine; anything that would cross 10 GB needs a yes first (≈ $0.015/GB-month).
  Egress is free. Class A/B operations must stay in the free tier, so use one object per movie (not one per chunk).
- Durable Objects, Workers paid features, or any Worker in the read path. The TV fetches R2 directly via presigned URLs.
- Decrypted bytes written to disk, or the decrypted stream exposed to other apps on the TV.
- Breaking the torrent build that Mom's TV runs.

## 3. Approaches considered

| | Approach | Trade-off | Decision |
|---|---|---|---|
| A | **Per-TV RSA keypair in Android Keystore; random key per movie, wrapped for each paired TV by the server** | More to build (pairing, key table, Keystore code); true "only on this TV"; revoke = stop serving the wrapped key | **Picked by the owner** |
| B | One shared key baked into the APK | Simple; anyone who pulls the key out of the APK reads every chunk | Rejected |
| C | Signed links only, plaintext MKVs in R2 | Smallest build; content visible to Cloudflare and to anyone holding a live link | Rejected (fails the core goal) |

## 4. Cryptography

### 4.1 Movie encryption (on the Mac)
- **Content key (CK):** 32 random bytes per movie (AES-256). Generated by the uploader.
- **Cipher:** AES-256-GCM, applied **per chunk**.
- **Chunk size:** 1 MiB plaintext (1,048,576 bytes). The last chunk may be shorter.
- **Nonce (12 bytes):** `file_nonce_prefix (4 random bytes, per movie) || chunk_index (uint64 big-endian)`.
  CK is unique per movie, so a counter nonce never repeats under one key.
- **AAD:** `"ADIK1" || movie_uuid (16 bytes) || chunk_index (uint64 BE) || is_last (1 byte)`.
  This binds each chunk to its movie and position. A swapped, reordered or truncated chunk fails the tag check.
- **Object layout (one R2 object per movie):**
  ```
  header (fixed 64 bytes, plaintext):
    magic "ADIKENC1" (8) | version u16 | chunk_size u32 | plaintext_size u64 |
    chunk_count u32 | nonce_prefix (4) | movie_uuid (16) | reserved/zero
  chunk i at offset 64 + i * (chunk_size + 16):
    ciphertext (chunk_size, last chunk shorter) | GCM tag (16)
  ```
  The nonce is computed, not stored. Chunk offsets are computable, so any byte range maps to a set of
  chunks that can be fetched with one HTTP Range request.
- **Object key in R2:** `v/<random 128-bit hex>`. No title, extension or size hints in the name.
  Bucket: `adik-stream` (new, private, no public access, no custom domain).
- The header reveals the plaintext size, which is acceptable. Titles and metadata never go to R2.

### 4.2 Device keys (on each TV)
- On first launch the app generates **RSA-3072** in **AndroidKeyStore**: purpose DECRYPT, padding
  OAEP, digest SHA-256 (MGF1-SHA1 for API < 31 compatibility; both server and TV must use the same params).
  Prefer StrongBox when present, else TEE. The key is non-exportable.
- Request **key attestation** (`setAttestationChallenge(server_nonce)`). The app sends the public key and
  attestation certificate chain at pairing. The server records `security_level` (StrongBox / TEE / software).
  v1 **records and shows** the level and does not reject software-backed keys, because cheap TVs may lack TEE
  attestation. The owner sees the level when approving.
- Minimum Android: API 23 (unchanged). Verified target: living-room TCL, Android 11 / API 30, armeabi-v7a
  with ARMv8 AES instructions; Mom's Sharp, Android 14.

### 4.3 Key wrapping (on main-server)
- The server stores each movie's CK **encrypted at rest** with a server master key
  (`ADIK_STREAM_MASTER_KEY`, 32 bytes, Coolify env, registered in tokenator). Cipher: AES-256-GCM.
- For a paired TV, the server returns `RSA-OAEP(device_public_key, CK)`, wrapped on demand.
  The plaintext CK exists only briefly in server memory and in the TV's process memory during playback.
- The CK is never sent unwrapped, logged, or written to the TV's disk.

## 5. Components

### 5.1 Uploader (Mac) — `~/Projects/Main/Tools/adik-curator/stream_upload.py` (new)
`stream_upload.py <file.mkv> --tmdb <id> --title "…" [--dry-run]`
1. Check R2 account usage first (all buckets) and **abort if this upload would push the account past 10 GB**,
   unless `--allow-paid` is passed (the owner must say yes first).
2. Generate CK, nonce prefix and movie UUID; stream-encrypt to the layout in §4.1 (no full-file temp copy;
   S3 multipart upload as it encrypts).
3. Upload to `adik-stream/v/<hex>` with the main-server R2 key (`tokenator exec r2-access-key-id r2-secret-access-key …`).
4. Wrap CK with the server master key and register the movie via `POST /adik/stream/movies`
   (admin-token gated, **insert-only**, same pattern as `/adik/movies/new`).
5. Self-check: download chunks 0 and N-1, decrypt and compare against the source.

Playable-format check before upload (ffprobe): video h264/hevc (≤ Main10), audio aac/ac3/eac3/mp3/opus,
container mkv/mp4. Otherwise warn. No transcoding in v1.

### 5.2 Server — `~/Projects/main/main-server/routes/adik-stream.js` (new, mounted at `/adik/stream`)
Tables (auto-created on boot, like `adik_device_items`):
- `adik_stream_devices (device_id PK, public_key_der, attestation_level, attestation_chain jsonb,
  status enum pending|approved|revoked, created_at, approved_at)`
- `adik_stream_movies (id slug PK, movie_uuid, tmdb_id, title, r2_key, plaintext_size, chunk_size,
  chunk_count, ck_wrapped_master bytea, added_at)`

Routes (all behind the existing token + device-id stealth-404 check):
- `POST /pair` `{device_id, public_key, attestation_chain, challenge}` → stores as `pending`. Idempotent.
  `GET /pair/challenge` issues the attestation nonce.
- `GET /movies` → list for an **approved** device (no keys, no R2 keys).
- `POST /play/:id` → for an approved device: `{wrapped_ck, header fields, url}`, where `url` is an
  **R2 presigned GET, valid 6 h**. Logged with device and title.
- Request authentication: the TV signs a server-issued nonce with a second Keystore key (**EC P-256 SIGN**,
  supported from API 23) registered at pairing. A stolen device id + token alone can't fetch wrapped keys.
  (The RSA key is for decryption only.)
- **Device identity:** the stream app does **not** use the hand-typed fleet ids. Its id is
  `S_` + the first 16 hex chars of SHA-256(RSA public key DER), so it's derived from the key and can't be
  claimed by someone else. The stream routes use the shared token, but not the `DEVICES[]` stealth-404 list,
  so a new TV can pair without a server code change. Approval is the gate.
- **Pairing code:** the "Waiting for approval" screen shows the device id plus an **8-character pairing code**
  (base32 of SHA-256 over both public keys). Approving needs that code:
  `adik-stream approve <code>` (small CLI on the Mac → admin-token route), which matches on the code and
  so approves exactly the key showing on the TV in front of the owner. Revoke: `adik-stream revoke <device_id>`.
  Status changes are `UPDATE`s; nothing is deleted.
- **Re-pairing (reinstall / data cleared / factory reset):** the new key produces a new device id, which
  arrives as a fresh `pending` row. Existing rows are never overwritten. The old row stays as it was until the
  owner revokes it (`adik-stream devices` lists them with last-seen time).

Deploy: commit + push main-server `master` (Coolify auto-deploys). Stage only these files.

### 5.3 TV app — new variant of `~/Projects/AdikTV`
- **Variant:** new product flavor `stream` → applicationId `com.adik.stream`, app name "ADIK Stream".
  It installs **next to** `com.adik.tv` and shares the UI/player code. The torrent/download/drive/night
  code is excluded from the `stream` flavor (source sets), so the APK drops libtorrent4j.
- **`StreamKeys`**: creates or loads the RSA-3072 decrypt key and the EC P-256 signing key; runs pairing
  and attestation; shows "Waiting for approval — device <id>" until approved.
- **`StreamCatalog`**: `GET /adik/stream/movies` → library rows (reuses TMDB art like today).
- **`DecryptingProxy`**: an HTTP server on `127.0.0.1` with a random port, serving one URL
  `http://127.0.0.1:<port>/<random 128-bit session secret>/movie`.
  - Supports `Range` requests. It maps the plaintext range to chunks, fetches the ciphertext range from the
    presigned URL (OkHttp, keep-alive), verifies + decrypts each chunk with AES-GCM, and returns plaintext.
  - Reads ahead 4–8 chunks; holds at most ~16 MiB of plaintext in memory; never writes plaintext to disk.
  - Rejects any request with the wrong session secret. It lives only while the player is open, and the CK
    is zeroed on close.
  - Re-requests `/play` when the presigned URL nears expiry (long pauses).
  - On a GCM tag failure it retries that chunk once, then surfaces a playback error (never plays unverified bytes).
- **Player:** `VlcPlayerViewModel` already accepts any `Uri` (`toVlcUri`). Pass the proxy URL.
  libVLC sees a normal seekable HTTP MKV. Turn on libVLC's network caching (~3000 ms) for this source.
- **Updates:** the self-updater stays on, in a separate channel. Stream releases are tagged `stream-v*` in
  `T31K/adik-tv` with an asset named `adik-stream-*.apk`. Each flavor's updater filters on its own tag
  prefix (a `BuildConfig` field), so neither app can pull the other's APK. Torrent releases keep their current tags.

### 5.4 Player redesign (both flavors) — `ui/screens/player/VlcPlayerScreen.kt`
The owner wants the Netflix player layout exactly (reference screenshot supplied 2026-11-27): the same
layout and controls, using ADIK's own icons/fonts and no Netflix logo or branding. The old ARVIO
ExoPlayer screen already had this layout (`git show 7b421ad^:app/src/main/kotlin/com/arflix/tv/ui/screens/player/PlayerScreen.kt`:
centre rewind/play/forward cluster ~L4100, seek bar + remaining time + labeled action row ~L4144–4440,
`PlayerIconButton`/`PlayerLabeledButton`). **Port that chrome onto the libVLC player** rather than designing from scratch.
It's shared code, so the torrent app gets it too.
```

│        ⟲10                   ❚❚                   10⟳         │

```
- **Top:** back arrow top-left; the title **centred at the top** (movie title, or `S4:E1 "Episode name"`
  for episodes), taken from the catalog/TMDB. It **never shows a filename or URL** (today's ugly filename text goes).
- **Centre:** a large play/pause in the middle, with circular "10" rewind and forward icons on either side,
  spaced wide.
- **Seek bar:** thin full-width line with a red round knob; the played part is red; **time remaining** on the right.
- **Bottom row:** labeled buttons "Episodes" (series only) and "Audio & Subtitles". No "Next episode" button.
- No cast or screenshot buttons (TV app).
- D-pad: left/right = ±10 s; holding = scrub; OK = play/pause; up/down moves focus between the centre cluster,
  the seek bar and the bottom row. The controls fade after ~3 s of no input, and dim gradients sit top and bottom only.

## 6. Rollout

1. **Spike (approved separately, throwaway):** plaintext upload of the Demon Slayer file plus a presigned URL
   played on the living-room TCL. This proves R2 → TV throughput and libVLC HTTP seeking. Delete the
   object afterwards (the owner runs the delete; see their DB/data rules).
2. Build the encrypted format + uploader; test round-trips on the Mac.
3. Server routes + tables; pair the living-room TCL (192.168.100.12) only.
4. `stream` flavor on the living-room TCL; play Demon Slayer end to end; test seeks, subtitles and a long pause.
5. Mom's TV only after the owner says so (rule: no installs while she's watching).

## 7. Decided by the owner
- Stream from R2 instead of a USB drive (second version of the app).
- Approach A: per-TV keys in Android Keystore, per-movie keys wrapped per TV.
- "Best encryption possible" → AES-256-GCM chunks + RSA-3072-OAEP wrapping in Keystore + attestation.
- Spike passed (2026-11-27): 30-min plaintext clip from R2 streamed and played fine in VLC on the living-room TCL.
- Player = Netflix layout exactly per the reference screenshot, without the screenshot, cast and Next-episode buttons;
  reuse the old ARVIO player chrome.
- v1 scope = test on the living-room TV only: streaming + new player + encryption. Every approved TV sees every movie.

## 8. Calls made by Claude (correct any of these)
- Separate flavor/app (`com.adik.stream`) **alongside** the torrent app, not replacing it.
- One R2 object per movie with Range reads (cheaper than one object per chunk).
- 1 MiB chunks; 6 h presigned URLs; a localhost proxy in front of libVLC.
- Approval by DB `UPDATE` / small CLI rather than an admin UI.
- Software-backed keystores allowed but flagged in v1.
- Movies only in v1.
- Stream device ids derived from the key; approval by an 8-char pairing code shown on the TV.
- Re-pairing creates a new pending device and never overwrites an approved key.
- Separate `stream-v*` update channel in the same GitHub repo.
- Netflix-layout player (ported from the old ARVIO chrome) applies to both flavors.

## 9. Left to the builder

- Exact read-ahead tuning; libVLC caching values.
- Uploader language detail (Python `cryptography` + `boto3`), multipart part size.
- Test layout (JVM unit tests for chunk math, nonce/AAD construction, the header parser and tamper rejection).
